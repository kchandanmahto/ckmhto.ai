# Security Policy

## Security Philosophy

Security is an important part of the ckmhto.ai application.

The project follows a security-conscious approach across:

- Frontend
- Backend
- APIs
- Database
- LLM integration
- Environment configuration
- Deployment

---

## Supported Versions

Security fixes are generally applied to the actively maintained version
of the project.

| Version | Supported |
|---|---|
| Latest development version | Yes |
| Older versions | Limited / No |

Because this is an actively evolving portfolio project, security support
may change as the architecture develops.

---

## Reporting a Vulnerability

If you discover a potential security vulnerability, please report it
privately to the project maintainer.

Do not immediately create a public GitHub issue containing:

- Exploit details
- Credentials
- API keys
- Database credentials
- Private URLs
- Personal information
- Proof-of-concept code that could enable exploitation

A private report allows the issue to be investigated responsibly.

---

## What to Include

A useful security report should include:

### Description

Explain the vulnerability clearly.

### Impact

Describe what an attacker could potentially do.

### Reproduction

Provide minimal steps to reproduce the issue.
